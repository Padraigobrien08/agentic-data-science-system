# Milestone v1.2: Chat-First Analysis Experience

**Status:** ✅ SHIPPED 2026-04-19
**Phases:** 12-16
**Total Plans:** 15

## Overview

`v1.2` turned workspace chat into the primary answer-reading surface for the EDGAR product. It repaired the runtime and onboarding seams that broke first-run delivery, broadened deterministic analyst-language routing, moved completed answers into chat, attached inline findings and evidence navigation to the chat answer, and reduced the standalone run page to a secondary verification surface.

## Phases

### Phase 12: Runtime Reliability for Chat Delivery

**Goal**: Users can rely on the documented local stack to create run workspaces, execute runs, report background-delivery degradation truthfully, and enter the product through capability-aware onboarding before chat becomes the primary answer surface.
**Depends on**: Phase 11 milestone archive baseline
**Plans**: 3 plans

Plans:

- [x] 12-01: Repair worker/runtime boot and strengthen the documented Compose smoke around synchronous and queued execution
- [x] 12-02: Make chat sync-first with truthful background-delivery disclosure instead of a brittle worker-first default
- [x] 12-03: Add capability-aware onboarding so secure-default stacks stop advertising dead-end registration

**Details:**
- Requirements: `RUN-01`, `RUN-02`, `RUN-03`
- Outcome: the documented stack now supports reliable chat-triggered runs, truthful delivery posture, and first-run auth guidance

## Milestone Summary

**Decimal Phases:**

- None

**Key Decisions:**

- Decision: keep chat sync-first until background delivery was truthful and stable in the documented stack
- Decision: keep prompt routing deterministic-first and expose rewrite guidance before run creation
- Decision: move the answer, findings, and first-pass evidence navigation into chat before simplifying the run page
- Decision: treat the standalone run page as a secondary inspection surface rather than another answer reader

**Issues Resolved:**

- Repaired worker/runtime and onboarding seams that blocked first-run chat usage in the documented stack
- Removed unsupported-intent dead ends from the primary chat flow
- Consolidated answer reading and first-pass verification into chat instead of splitting it across chat and run pages

**Issues Deferred:**

- Compare or revisit multiple prior runs within one conversation thread
- Curate grouped evidence bundles from chat findings for later review or sharing
- Add richer chat thread persistence and organization beyond the current run-backed transcript model

**Technical Debt Incurred:**

- No milestone blockers remain after the clean audit pass
