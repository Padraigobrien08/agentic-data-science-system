# v1.6 Roadmap Archive

**Milestone:** `v1.6 Measured Agency and Visible Observability`
**Shipped:** 2026-08-08

## Sequencing note

Recorded retroactively, and numbered **after** `v1.5 Durable Chat History` even though it
shipped first. v1.5 was already claimed by the chat-history milestone across four planning
documents when this work began; taking the next free number avoided a second collision, at the
cost of the milestone sequence no longer matching ship order.

This was an unplanned track. It began as an evaluation of the repository against its own thesis
— an observable agent-orchestration system for complex analysis, exposed over MCP — and became
the work that closed the largest gap that evaluation found.

## Phases

- Phase 31: Agency Benchmark Under Real Models
- Phase 32: Agency Suite Hardening
- Phase 34: Observability, Demonstrated

Phase 33 (Multi-Metric Investigations) is scoped but **not executed**, and is deliberately not
counted here. It is carried forward unassigned.

## Delivered

- **The agency suite measured against a live model for the first time.** `ModelAgentPolicy` had
  no non-test callers; every claim about adaptive reasoning described a keyword table.
- **Versioned, registry-managed prompts for the four model-backed policy decisions**, replacing
  four inline string literals, with `prompt_id`/`prompt_version` exposed for attribution.
- **A multi-trial benchmark harness** that reports variance, per-case stability, cost and
  latency — because one pass of a non-deterministic policy is an anecdote.
- **A hard tier with an enforced admission rule**: a case earns its place only by defeating the
  deterministic baseline on a named reasoning property, checked free on every PR.
- **A published scoreboard** that discriminates: on the hard tier the rule engine scores 0% and
  `gpt-5.4-mini` 75%, stable across five trials.
- **The agent-loop dashboard, working and shown.** Four defects meant the documented
  observability stack could not render a dashboard at all.
- **Regression floors and a headroom ceiling** on the agency suite, plus static guards on
  compose env forwarding and Grafana dashboard validity.

## Findings worth more than the features

- **`suite_agency_v1` was saturated.** A keyword-matching rule engine and a frontier model both
  scored 100% on every property. Published as the headline rather than dressed as a pass.
- **A one-word prompt defect cost 38 points.** The critic prompt said to decline "with nulls",
  but only two of five fields are nullable; a null `message` tripped the loop's fail-safe and
  lost every converging case. Versioned prompts made the before/after comparable.
- **The model does not decline.** It reasons well about *what* to analyse and fails the one case
  where the data cannot answer the question — reaching `supported` at confidence 0.95.
- **An investigation can examine only one metric.** Every tool is parameterised from a single
  `metric_hint`, stranding a second hypothesis at `proposed` however well the agent reasons.
  This is what Phase 33 exists to fix.
- **The observability stack had never worked.** The engine flag and price table were not
  forwarded by compose, the Prometheus credential file was unreadable by Prometheus, and the
  dashboard JSON used a colour mode Grafana rejects.

## Carried forward
