- `AGCY-01` — versioned, registry-managed prompts for the policy surface
- `AGCY-02` — prompt identity available for attribution (partial: exposed and logged, not
  persisted to `ModelCall`; see below)
- `AGCY-03` — multi-trial model-backed suite execution with variance, cost and latency
- `AGCY-04` — a committed, reproducible scoreboard
- `AGCY-05` — per-property regression floors enforced by the free offline suite

- `HARD-01` — `suite_agency_v1` frozen and independently runnable
- `HARD-02` — an enforced admission rule for the hard tier
- `HARD-03` — a discriminating case set spanning several properties, both failure directions
- `HARD-04` — per-tier reporting that never averages core and hard together
- `HARD-05` — the measurement published as observed

Phase 34 — Observability, Demonstrated:

- `OBS-01` — a varied, free, offline workload that populates the dashboard
- `OBS-02` — the dashboard captured with its three health checks visibly passing
- `OBS-03` — placed in the README with explicit framing and a reproduction path

## Not Delivered

- `MULTI-01` … `MULTI-05` — Phase 33 (Multi-Metric Investigations) is scoped but not executed.
  Carried forward unassigned.

## Partial

- `AGCY-02` was scoped as "prompt identity lands on `ModelCall`". That path does not exist for
  the agentic policy: `CostTrackingResponder` calls the provider directly, and `ModelCall` rows
  are written only by `RecordedChatCompletionService`, which needs a `Session` and an
  `analysis_run_id` that `build_agent_policy(settings)` has no access to. Identity is exposed on
  the policy object and logged, which satisfies the benchmark's needs; product runs still
  produce no `ModelCall` rows for the four policy decisions.

## Summary

The milestone turned the repository's strongest untested asset into a published result. The
agency suite existed and was well designed, but had never been pointed at a model; doing so
found it saturated, hardened it until it discriminated, and produced a scoreboard reporting a
75-point gap between a rule engine and `gpt-5.4-mini` on the hard tier.

It also found that the documented observability stack could not render a dashboard at all, and
that the loop can only ever examine one metric — the latter now scoped as Phase 33.

Every new guard in this milestone was mutation-checked, a practice adopted after two of the four
guards written in Phase 31 passed with the bug deliberately restored.
